| nestjs-v1-q19 | confirmed | https://vite.dev/guide/migration ; https://vite.dev/guide/features | Edit only narrows Vitest to "Vite 7 or older". | nestjs-v2-q10 | confirmed | https://github.com/nestjs/nest/blob/master/packages/microservices/client/client-kafka.ts | `publish()` calls `getReplyTopicPartition()`, which throws InvalidKafkaClientTopicException ("The client consumer did not subscribe to the corresponding reply topic (<topic>).") when `consumerAssignments[topic]` is undefined. That happens before `producer.send`. `setConsumerAssignments` skips topics with zero assigned partitions, so a pod with none hits it. The error goes to the caller via errorCallback, so "fail before sending" is right and the old "time out" was wrong. Key (partitions >= pods) is the sole defensible answer. |
| nestjs-v2-q15 | confirmed | https://github.com/nestjs/nest/blob/v11.1.0/packages/core/nest-application-context.ts ; https://docs.nestjs.com/fundamentals/lifecycle-events | v11 sorts modules by `distance` desc and runs destroy/beforeShutdown/shutdown on `.reverse()` of that, so it is module by module. v10.4.15 has 0 `reverse()` calls, v11.0.0 has 3, so "Nest 11 changed it" is true. The lifecycle docs say the same: deepest imported and global modules go first on init, shutdown in reverse. New wording (AuditModule imports DatabaseModule, so Audit is destroyed first) is correct. The old "provider injection order" claim was not what the code does, so the new one is more correct. Caveat: Nest 12 docs say hooks are now called "by component hierarchy level", so the claim is Nest 11 only. Nit: the v11 migration guide in refs does not mention hook order. |
| nestjs-v2-q17 | confirmed | https://vite.dev/guide/migration ; https://vite.dev/guide/features ; https://oxc.rs/docs/guide/usage/transformer/typescript.html ; https://docs.nestjs.com/recipes/swc | Stem now pins Vite 7 (esbuild). Vite 8 uses Oxc, whose emitDecoratorMetadata support falls back to `Object` where types need inference, so "partly" is accurate. Nest's own recipe still uses unplugin-swc for Vitest. Key (unplugin-swc) is the sole correct option. Vitest 5.0.5 (current) allows vite ^6.4 / ^7 / ^8, so Vite 7 pairing is realistic. |
| nestjs-v3-q18 | confirmed | https://docs.nestjs.com/faq/serverless (raw: .../content/faq/serverless.md) | Official recipe uses `webpack.IgnorePlugin` with `lazyImports = ['@nestjs/microservices/microservices-module', '@nestjs/websockets/socket-module']`, ignoring them if `require.resolve` fails.
