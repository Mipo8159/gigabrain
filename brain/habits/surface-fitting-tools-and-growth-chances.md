**Rule:** while working, name the improvement chance the moment it is real: an org
plugin skill or MCP that fits the next step, a team convention the work should follow,
or a Claude feature (subagent, worktree, hook, plan mode, `claude -p`) that would have
paid off. One short "Improvement:" line each, tied to what just happened; then continue.

**Why:** said explicitly 2026-11-20 ("my final aim to be as competent with <work org>
and as proficient with claude usage as possible, so if chance for improvements arise,
tell me about them"), after asking which org skills fit a migration and finding only one
had been used. A scan of the org plugin list then found 4 that fit later steps (TDD
standards for a deploy-script change, the PR review skill, the PR template command, a
staging-booking skill) and showed the org's KPI MCP had no data lenses for the numbers
the work needed.

**How to apply:** when the skill list changes or a step starts, check the org plugin's
skills against the step (fit / optional / skip, one table at most when asked). Report the
honest gap too ("none of these gives historical numbers; NR via the existing access does").
Never a generic tips list; no lecture. Org facts stay in local project memory.

**Signal:** a new step or phase starts; a system reminder lists newly available skills;
Giga asks "is there a skill/tool for this".
**Next time:** one line per real fit, with the step it serves.
